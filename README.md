# 推广创作台（dsh-studio）

> 仓库：https://github.com/gzyxds/dsh-studio-plugin
> 安装与使用：[INSTALL.md](INSTALL.md)

把上游给的商品原文，变成可以直接发出去的自媒体推广素材。

## 它解决什么问题

流量卡这个品类，平台审得严：写「永久 19 元」是虚假资费，写「不限量」是绝对化承诺，
写「官方授权」是虚假资质，写归属地会被判违规宣传。运营同学手上只有一段渠道给的
原始文案，要人工拆成小红书笔记、抖音口播、快手表图文案，还要配一张能发的卡片图——
同一份事实反复抄五遍，抄错一个数字就是一次处罚。

这个插件把这条链路收成三步：

1. **粘贴原文 → 自动结构化**。从自由格式的商品单里识别月租、通用流量、通话、
   首充、合约期、运营商、发货地区、激活方式等 14 个字段，并标出哪些没识别到。
2. **合规体检**。20 条规则扫原文，分成「必须改」「建议改」两级，命中项给出原因和
   改法（永久 → 长期、归属地 → 发货地、100% → 实测）。
3. **出文案 + 出图**。按平台（小红书 / 抖音 / 快手 / 朋友圈 / 视频号 / 微博 /
   B 站 / 社群）和体裁（种草 / 直给 / 故事 / 讲价值 / 问答）生成多条文案，自动带
   `#标签`，可一键复制；再按 9:16、16:9、1:1、4:3、3:4 出卡片图，可下载。

## 安装

**看 [INSTALL.md](INSTALL.md)** —— 从 GitHub 下载之后怎么装进 DeepSeek Harness、
怎么用、怎么排查，里面写了完整步骤。这里只给最短路径：

1. 下载 ZIP 解压到一个固定目录（必须解压，且指向含 `package.json` 的那一层）；
2. DSH 侧边栏 →「插件」→ **Add plugin** 右侧箭头 → **Install a third-party plugin** →
   粘贴那个目录的绝对路径 → Install；
3. **完全重启 DSH**；
4. 侧边栏出现「推广创作台」图标。

> `lib/` 是构建产物，但**故意提交进仓库**：从目录或 Git 安装时不会再跑构建，
> 客户拿到就能装。改 `src/` 之后必须 `npm run build` 再重新打包分发。

## 使用

侧边栏点「推广创作台」图标：

1. 把商品原文整段粘进左上角文本框，点「解析」（不知道格式可以先点「填入示例」）。
2. 左中核对识别结果，数字不对就直接改；左下看合规体检。
3. 右栏「推广文案」页签选平台和体裁，点「生成文案」，逐条复制。
4. 右栏「卡片图」页签选尺寸和配色，点「生成卡片图」，满意后「下载图片」。

推广链接和二维码链接是同一个东西的两种用法：填了链接，文案的行动指令后面会带上它；
填了二维码链接，卡片图上会画二维码。都留空也能出完整素材。

## 设计上的几个取舍

- **不调模型**。文案由模板引擎生成，同样的输入永远得到同样的输出，运营可以预期、
  可以回归测试，也不受网关配额和延迟影响。生成速度是毫秒级。
- **合规规则是数据，不是代码**。规则表里每条都有正则、级别、原因和建议改法，
  新增一条不需要改渲染逻辑。
- **出图用 canvas，不用截图**。「先量后排」——先用干跑上下文量出每个区块的真实高度，
  再按权重分配纵向空间，所以标题超长、字段全空、没有二维码这些边界情况都不会溢出。
- **配色只吃主题令牌**。所有颜色来自 `--dsw-alias-*`，切换 DSH 的明暗主题时界面
  跟着变，不会出现一块刺眼的白底。

## 开发

```bash
npm install
npm run build     # src/client → lib/client.js
npx tsc --noEmit  # 类型检查
```

改完代码重新 `npm run build`，然后在 DSH 里重载插件（或在插件管理里禁用再启用）。

### 测试

```bash
node --experimental-strip-types scripts/smoke.mjs   # 离线：引擎 + bundle + 插槽注册 + 渲染
node scripts/e2e.mjs                                # 浏览器：真页面跑完整链路，截图落 .tmp-e2e/
```

`scripts/e2e.mjs` 借用 `D:\github\urlka.cn` 里的 playwright，本包不装浏览器依赖。

### 排错

- **侧边栏没出现图标**：插件装好后必须重启 DSH；重启后仍未出现，先确认
  `~/.dsh/profiles/desktop/package.json` 的 `dsh.profile.bundles` 里有 `dsh-studio`。
- **界面没样式 / 停在旧样式**：`injectStyles` 每次都会先删旧 `<style>` 再插新的，
  如果仍不对，检查 `document.head` 里 `style[data-plugin-css="dsh-studio/studio.css"]`。
- **改完代码界面没变**：静态 bundle 不走 HMR，需要 `npm run build` 后在插件管理里重载。

## 目录

```
INSTALL.md         面向使用者的安装与使用指南（从 GitHub 下载之后看这个）
src/lib/studio/    引擎：解析、合规、平台、文案、标签、尺寸、主题、出图
src/data/config/   运营商元数据
src/utils/         通用解析工具
src/client/        界面：状态钩子、面板、字典、样式
scripts/           构建、离线冒烟、E2E 宿主壳
lib/               构建产物（client.js 是打包后的浏览器入口）——已提交，勿删
locale/            插件显示名与描述
```

### 发布前检查

分发给客户之前，确认这三件事：

1. `lib/index.js` 与 `lib/client.js` 是最新构建（`npm run build` 之后再打包）；
2. `node_modules/` 和 `.tmp-e2e/` 不进压缩包（`.gitignore` 已覆盖）；
3. `package.json` 的 `files` 与实际交付的目录内容一致。
